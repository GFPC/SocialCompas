# 🧭 Социальный Компас (SocialCompass)

Единая цифровая экосистема социального навигатора для **MAX Messenger** (чат-бот + мини-приложение) — помогает находить скидки, акции, льготы, культурные площадки и социальные программы для **студентов**, **пенсионеров** и **участников СВО** в городах России (Москва, Санкт-Петербург, Новосибирск).

## Назначение решения

Сервис **SocialCompass** решает проблему сложного и разрозненного поиска льгот, акций и доступных досуговых мест для социальных категорий граждан (студенты, пенсионеры, участники СВО).
Решение реализовано как чат-бот в **MAX Messenger**, интегрированный с единым веб-приложением (**MiniApp**), предоставляющим интерактивную карту, списки мест, личное избранное и ИИ-гида по акциям.

---

## Основной пользовательский сценарий

1. **Онбординг**: Пользователь пишет боту в MAX и проходит 2 быстрых шага: выбор города (Москва, Санкт-Петербург, Новосибирск) и льготной категории (Студенты, Пенсионеры, Участники СВО).
2. **Открытие мини-приложения**: бот подсказывает, что мини-приложение открывается **нативной кнопкой приложения рядом с полем ввода сообщения** (а не кнопкой под сообщением). Оно открывается шторкой внутри MAX; MAX передаёт `initData` с тем же `user.id`, что и в боте.
3. **Просмотр каталога**: главный экран со списком мест и акций для профиля пользователя. Переключение «Список» / «Яндекс Карта» (метка на каждый адрес места).
4. **Фильтрация и детали**: фильтр по типам площадок (Музеи, Театры, Аквапарки, Боулинг, Котокафе, Спорт). Карточка места: адрес, график, размер скидки, ссылка на сайт, кнопка «Поделиться» (нативный диалог MAX).
5. **Избранное**: сохранение мест в личное избранное; доступно только владельцу (проверка токена на сервере).
6. **ИИ-Гид (AI Tunnel)**: вопросы ассистенту с учётом реальных мест из базы; на посторонние темы вежливо отказывает.
7. **Синхронизация бота и мини-приложения**: профиль и избранное хранятся по MAX `user_id`; смена города или категории в боте видна в мини-приложении (при возврате в приложение или в течение ~20 секунд) и наоборот, без повторного онбординга.

**Использованные возможности платформы MAX сверх минимума:** авторизация по подписанному `initData` (HMAC-SHA256) вместо ввода данных; нативная кнопка «Назад» (`BackButton`) на карточке места; вибро-отклик (`HapticFeedback`) при добавлении в избранное и ошибках; нативный диалог «Поделиться» (`shareMaxContent`/`shareContent`); `WebApp.ready()`. Вне MAX мост отсутствует, и приложение работает как обычный сайт (гостевой режим).

## Команда для запуска всех локальных компонентов через Docker

```bash
cp .env.example .env        # заполните MAX_BOT_TOKEN (и AITUNNEL_API_KEY для ИИ-гида)
docker compose up -d --build
```

Сборка образа с нуля (без кэша, базовые образы уже скачаны) занимает около 1–2 минут. В образ входит сборка мини-приложения (multi-stage: Node → Python), поэтому **одна команда поднимает всё**: MiniApp, REST API, бота, MySQL и Redis.

При первом запуске с пустой БД приложение автоматически:
1. создаёт схему и загружает каталог из `data/*.xlsx` (87 мест);
2. в фоне вычисляет координаты меток на карте по адресам (OpenStreetMap Nominatim, ≈1 запрос/с, несколько минут; пока метки появляются постепенно, каталог и остальные функции уже работают).

После запуска доступно:
- **MiniApp (SPA)**: `http://localhost:8000`
- **Swagger UI**: `http://localhost:8000/docs` (`ENABLE_DOCS=true` в локальном compose)
- **OpenAPI**: `http://localhost:8000/openapi.json`
- **Healthcheck**: `http://localhost:8000/api/v1/cities`

Без реального `MAX_BOT_TOKEN` API и MiniApp в браузере работают, но бот не получает сообщения (MAX отвечает 401).

## Внешние сервисы и интеграции

1. **MAX Platform API** (`https://platform-api2.max.ru`): приём обновлений (long polling) и отправка сообщений бота. Сертификат выпущен Russian Trusted Root CA — публичный корневой сертификат лежит в `certs/`, проверка TLS включена.
2. **MAX Bridge** (`window.WebApp`, скрипт `https://st.max.ru/js/max-web-app.js`): `initData`, `BackButton`, `HapticFeedback`, `shareMaxContent`.
3. **AI Tunnel API** (`https://api.aitunnel.ru/v1`): LLM для ИИ-гида.
4. **Яндекс Карты JS API 2.1**: отображение карты и меток.
5. **OpenStreetMap Nominatim**: геокодирование адресов каталога в координаты (один раз, результат хранится в БД, `places.points`).

## Описание работы с данными

- **Каталог мест** (`places`, 87 записей) собран из открытых сведений о льготах и акциях площадок и лежит в `data/БД акции по городам.xlsx` и `data/Санкт-Петербург.xlsx`; при первом запуске импортируется автоматически. Актуальность условий скидок нужно уточнять у площадок.
- **Метки на карте**: `places.points` (JSON `[{lat, lng, address}]`) — по одной точке на каждый адрес места; вычисляются геокодером из адреса. Точность зависит от полноты адреса: для сложных адресов точка может встать на улицу, для адресов без конкретики («Различные адреса», «Сеть кинотеатров») метки нет.
- **Профили и состояния**: `user_profiles`, `user_states` (MySQL) и FSM в Redis; ключ везде — MAX `user_id`. Избранное: `user_favorites`.
- **Доступ к данным пользователя**: Bearer-токен выдаётся только после проверки подписи `initData` и привязан к `user_id`; чужие данные недоступны (403). Вне MAX используется анонимный `guest_*` id.

### ⚠️ Смоделированные и тестовые данные

- **Тестовые аккаунты** (`data/test_accounts.json`, `user_id` 998877 / 554433 / 112233) — **вымышленные**, нужны только для проверки API.
- Если файлы `data/*.xlsx` отсутствуют, приложение засевает **небольшой набор смоделированных демо-мест** (вымышленные описания, ссылки-заглушки); в поставке репозитория этого не происходит — используется реальный каталог.
- `data/test_data.json` — пример структуры ответов API для тестов.

## Пошаговый сценарий проверки

### 1. Основной сценарий в MAX
1. Откройте бота в MAX (ссылка на служебном слайде) → `/start` → выберите город и категорию.
2. Нажмите кнопку мини-приложения рядом с полем ввода сообщения — приложение откроется шторкой внутри MAX.
3. Проверьте каталог, карту (метки по адресам), карточку места (нативная кнопка «Назад», «Поделиться»), избранное, ИИ-гид.
4. Смените город в боте (⚙️ Настройки профиля → ✏️ Изменить данные) — вернитесь в мини-приложение: город обновился. Затем смените в мини-приложении (вкладка «Профиль») — напишите боту `/menu`: профиль в боте обновился.

### 2. Автотесты (бот, FSM, JWT, изоляция пользователей, ИИ)
```bash
python test_bot.py
```

### 3. Сквозная проверка контракта API против запущенного стенда
```bash
docker compose up -d --build
MAX_BOT_TOKEN=<токен бота> python scripts/check_api.py                 # http://localhost:8000
BASE_URL=https://api.socialcompass.ru MAX_BOT_TOKEN=<токен> python scripts/check_api.py
```
Скрипт подписывает `initData`, получает токены двух пользователей и проверяет каталог, авторизацию, 401/403, избранное, профиль, ИИ-чат.


## Известные ограничения

1. **Swagger UI на продакшене** отключён (`ENABLE_DOCS=false`); локально через Docker включён.
2. **Лимит ИИ-запросов**: 10 в минуту на IP (`CHAT_RATE_LIMIT_PER_MINUTE`). Без `AITUNNEL_API_KEY` ИИ-гид отвечает заглушкой.
3. **География MVP**: Москва, Санкт-Петербург, Новосибирск; каталог — статический файл Excel, автоматического обновления условий скидок нет.
4. **Карта**: метки строятся геокодером OpenStreetMap по тексту адреса — часть точек приблизительна (улица вместо здания), для адресов без конкретики метки нет; первое построение на чистой БД занимает несколько минут. Если Яндекс Карты запросят ключ, задайте `VITE_YMAPS_KEY` при сборке.
5. **Вне MAX** мини-приложение работает в гостевом режиме (`guest_*`, без синхронизации с ботом); нативные функции моста (кнопка «Назад», вибро, «Поделиться» через MAX) недоступны.
6. **id мест** задаются при импорте каталога; `DATA-API.yaml` ссылается на id, существующий на боевом сервере (4004); в свежей локальной БД id начинаются с 1.
7. **Токен пользователя** действует 30 дней; при истечении мини-приложение запрашивает новый по `initData` автоматически.
8. Часть условий скидок — публичные сведения площадок на момент сбора данных; перед посещением рекомендуется уточнять на сайте площадки.
